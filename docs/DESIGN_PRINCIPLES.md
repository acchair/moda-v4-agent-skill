# 设计理念

moda-v4 的目标不是把更多数据堆成一张评分表，而是把“系统变化如何传导到公司利润、市场预期是否已经反映、什么证据会推翻判断”变成可复核的研究过程。

## 一、先形成逻辑，再调用数据

研究从最小事实包开始，不从完整采集器的结果直接跳到结论：

```text
用户问题
  → 系统变化
  → 产业链与利润池
  → 公司受益层级
  → 可证伪 Logic Case
  → 逐箭头支持证据与反证
  → 定向补证
  → 同行、预期差与赔率
  → Judgment V4
  → 五态与三项验证变量
```

完整证据流水线是 Evidence Service。它服务于已提出的逻辑问题，不替代逻辑本身。

## 二、事实、推断和行动分层

每个可见判断都必须能回答三件事：

1. 事实是什么，来自哪个来源；
2. 事实意味着什么，推断跨过了哪一步；
3. 对当前判断有什么影响，下一步如何验证或证伪。

`research_score`、覆盖率、F1-F6、技术指标和 Hard Cap 属于证据审计层。它们用于检查证据完整度、风险约束和时点，不直接替代产业逻辑，也不自动映射为买卖指令。

## 三、因果链必须可证伪

研究不只写“行业景气、公司受益”，而是明确拆出：

- 需求是否真的变成订单；
- 订单是否进入公司主营；
- 公司是否处在利润池的关键位置；
- 收入、利润和现金流是否开始兑现；
- 市场预期是否已经提前计价。

每条关键箭头都要有支持证据请求、反证请求和失效条件。第一个未验证或矛盾的箭头就是因果断点；缺口要转成两种可能及下一次验证方式，不能被默认值填平。

## 四、证据边界优先于信息数量

来源等级决定证据能做什么，而不是决定结论方向：

- 法定披露、交易所、政府和监管来源，用于确认正式事实；
- 行情和财经聚合数据，用于指标计算与交叉验证；
- 搜索、媒体、论坛、热榜和社交内容，主要用于发现候选线索。

搜索命中只有在来源匹配、正文可读、对象匹配和判断词匹配后，才可进入“未核验候选证据”。`搜索失败` 不等于 `已搜索未命中`，`未匹配` 不等于公司没有该业务，接口故障也不等于基本面不存在。

## 五、主营锚定产业链，同行决定选择质量

概念标签、板块名称和市场热度不能证明公司受益。公司定位必须从当前主营出发，回答它具体吃产业链哪一段、利润从哪里传来、是否具备技术/工艺/认证或客户关系等壁垒线索。

“为什么是它”必须和直接同行比较，至少覆盖业务纯度、产业链位置、利润兑现、竞争优势、最大缺陷、拥挤与预期以及估值赔率。无法验证优于同行时，结论应保留为“无法证明优于同行”，而不是强行选出龙头。

## 六、判断层和审计层各司其职

个股前台固定先讲：

1. 市场阶段与基本面阶段的唯一核心矛盾；
2. 主营锚定的产业链定位；
3. 为什么现在进入视野、过去为何受压及边际变化；
4. 可证伪假设、市场叙事与预期错位；
5. 同行选择、因果断点和 Bull/Base/Bear；
6. 历史估值情景、五态和恰好三项验证变量。

研究分、覆盖率、技术、六层评分、来源状态和缺口放在后方审计。板块输出只做行业逻辑和候选排序，不越权生成个股五态。

## 七、缺失要显式保留，降级要可追踪

每个数据服务都记录实际尝试过的来源、成功或失败状态、源日期、新鲜度和降级路径。系统区分主源成功、备用成功、确实无记录、请求失败和只能读取旧缓存。

缺失数据不会自动变成负面事实，也不会用旧报告静默补齐。覆盖率不足时降低判断状态；Hard Cap 仍直接约束五态：ST/退市强制退出，实控人减持或高位拥挤最高等待。

## 八、可复盘、可移植、可维护

Logic Case 保存当前版本与历史版本，便于复盘每一条逻辑箭头的证据变化。渲染保持确定性，采集、判断和表达相互隔离；跨平台差异通过来源降级和路径适配处理，而不是改变研究合同。

系统不连接交易账户，不保存 Cookie、密码、Token、API Key 或持仓信息，也不把人物表达当作实时事实。最终输出是研究假设与验证计划，不是收益承诺。
