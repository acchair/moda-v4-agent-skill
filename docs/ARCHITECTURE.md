# moda v4 架构

> 设计原则见 [DESIGN_PRINCIPLES.md](DESIGN_PRINCIPLES.md)；本文记录其对应的运行流程、边界和数据落点。

## 流程

用户可见的主流程是逻辑优先，原 13 模块保留为 Evidence Service：

```text
用户问题
  -> analyze_logic baseline（最小事实包）
  -> Logic Case（系统变化/产业链箭头/瓶颈/利润池/受益层级）
  -> 每条箭头的支持证据、反证与失效条件
  -> analyze_logic evidence（只补关键缺口）
  -> 同行竞争 + 市场预期 + 赔率
  -> 个股深度采集与 Judgment V4
  -> 五态 + 恰好三项跟踪变量
  -> F1-F6/覆盖率/技术/Hard Cap 审计附录
```

`tools/run_pipeline.py` 仍是完整证据流水线，不再是对话主入口。Logic Case 持久化在 `knowledge/research/logic_cases/{case_id}/`，板块主逻辑由候选公司共享；公司分支只回答受益层级和竞争差异。任何搜索结果在核验前都只能进入候选证据，不能把叙事升级为事实。

```text
股票代码/名称
  -> tools/run_pipeline.py
     -> 共享日 K 缓存
     -> 第一阶段并行采集（7 模块）
     -> 主营与行业上下文
     -> 申万二级行业映射与共享拥挤度缓存
     -> 第二阶段采集（供需、宏观政策）
      -> 第三阶段行业景气度交叉验证
      -> 结构化证据合并与 F1-F5 初评
      -> 完整版名单数据库查询（专精特新/行业龙头/核心供应商）
      -> 定向搜索需人工确认/部分覆盖项
     -> F1-F4 80 分 + F5 低位反转 10 分 + F6 修正项 10 分
     -> 研究分 + 证据覆盖率 + 五态决策约束
     -> 3 类 Hard Cap
     -> 固定格式 Markdown + JSON scorecard
```

## 关键边界

- `tools/scoring/evidence.py` 只读取本次运行后新生成的报告。
- 采集器通过 `<!-- moda_*: {...} -->` 输出结构化数据，Markdown 正文用于人工复核。
- `tools/scoring/model.py` 是唯一评分规则源。
- `tools/scoring/grader.py` 只负责合并、评分和报告渲染。
- 报告渲染使用固定宽度文本进度条；六段最终判断使用粗体标题、空行和正文，位于开头且结尾不重复输出。
- `tools/daily_cache.py`提供上海自然日 JSON 缓存、原子写入、排他锁及失败降级；日 K 另有跨运行日缓存和质量元数据，供财务与技术模块共享。
- `tools/akshare/industry_prosperity.py`负责申万行业映射、行业财务中位数、供需先行和市场验证，不直接改写评分。
- 共享日 K 按 easy-tdx、BaoStock、东财、新浪、腾讯降级；BaoStock 只按 B 级聚合行情使用。`ta` 计算 OBV、MACD、BOLL、ATR、DMI、RSI、WR，BIAS 按 30 日均线计算；缠论仅识别日线分型、笔和最近三笔重叠区间，同时输出当前价、支撑位、压力位和 0-4 技术结构分。
- BaoStock 财务摘要只做同报告期交叉验证和末级部分补缺，不替代 Sina/同花顺完整三表，不提升为法定披露证据。
- 量化选股筛选与投资逻辑追踪独立生成 0-2 机构方向分，不覆盖 easy-tdx 技术结构分。
- 其他机构方法在评分后运行，不向基础分、修正项或 Hard Cap 回写。

## 三阶段采集

第一阶段：财务、主营、技术、公告、市场事件、人气、社交热榜。社交模块同时采集个股讨论，直接接口失败后才搜索补缺。

行业上下文建立后：通过乐咕申万二级行业接口采集全量行业拥挤度；同一上海自然日只请求一次，其他股票共享缓存。

第二阶段：根据第一阶段得到的行业、主营和概念运行商品供需映射与宏观政策，减少错误行业匹配。

第三阶段：运行行业景气度交叉验证并初评 F1-F5；先查询 `专精特新_行业龙头_核心供应商_A股名单_完整版.csv`，命中的分类直接记录数据库证据，未命中的分类才进入定向搜索；合并未核验结果后统一终评。F3 龙头判断先按行业画像提取适用证据维度；研报标题只做线索，不直接给分。F6 始终使用原结构化数据链。

## 降级

- 单模块失败：记录失败，不读取旧报告。
- 商品映射未命中：不强行生成供需分。
- 搜索后端按 SearXNG、DuckDuckGo MCP、公共 DuckDuckGo、带引用模型搜索逐级回退；全部未配置、403 或超时才记录 `搜索失败，需人工确认`。
- 搜索缺口保留 75 秒全局时间预算，默认首轮覆盖全部 F1-F5 缺口；仅配置 `MODA_GAP_FIRST_PASS_LIMIT` 时才启用额外目标上限，并记录预算耗尽、跳过和人工确认原因。查询按公司、产业、产业链、利润兑现和市场预期的证据类型选择来源。
- 搜索覆盖 F1-F5 的 24 个子因子；只有来源匹配、正文可读且对象/判断词匹配时，才形成 `网络命中（未核验）`。标题或摘要孤立命中仅保留为待补证，结构化证据优先且不得被覆盖。
- 公告覆盖不足，或质押/解禁请求失败、比例字段缺失时，只保留状态和已命中的正向风险证据，不生成“稳定”“安全”或零比例结论。
- 公告催化必须由有日期的明确事件构成；金额、数量、产能、同比或项目动作等硬细节用于区分可确认事件和普通标题线索。终止、取消、延期、下降、过剩等反向词排除。
- 公司资本开支需要 CAPEX、在建工程、固定资产投资或带硬细节的扩产事件；订单增长只能作为辅助证据，不能单独确认资本开支浪潮。
- 完整版名单数据库命中后，不为对应的专精特新、行业龙头或核心供应商分类重复分配网络搜索预算；未命中的分类仍可搜索补缺。
- 巨潮资讯、沪深北交易所为法定信息披露来源；雪球、东方财富、大智慧等金融论坛只保留为线索，不进入确认器。
- 社交平台失败：其他平台继续；少于 3 个平台可用时热度标记不完整。
- 拥挤度和行业表按上海自然日每天检查一次；检查日期不替代源数据日期。
- 乐咕拥挤度过期或刷新失败时，尝试申万二级指数成交额/成交量滚动分位代理；代理也不可用时旧值只展示，不计分、不触发 Hard Cap。
- 行业景气映射失败、乐咕 403 或报告期不完整：标记 `部分/不可用`，不使用概念板块补位。
- 乐咕属于 B 级聚合数据，雪球文章属于 C 级方法线索；两者只影响证据确信度。
- 报告正文以 Agent Judgment V4 先展示市场/基本面阶段错位、主营锚定的产业链、旧矛盾的边际变化、预期差、因果断点和五态；研究分、覆盖率和技术指标退到证据审计层，不保留旧交易评级字段。缺失项计入 `unknown_maximum`，不生成负面事实。
- 覆盖率低于 60% 时五态最高为观察；ST/退市强制退出，实控人减持和高位拥挤最高等待。

## 输出目录

- `knowledge/research/{module}/{code}.md`：模块证据。
- `knowledge/research/scoring/{code}.md`：最终固定格式报告。
- `knowledge/research/scorecards/{code}.json`：证据与评分结构。
- `knowledge/research/pipeline/{code}.json`：本次模块状态。
- `knowledge/research/web_research/{code}.md`：搜索查询、正文读取状态和交叉验证结果。
- `knowledge/research/industry_prosperity/{code}.md`：行业映射与三层景气交叉验证。
- `knowledge/research/sectors/{sector}.md`：板块事实包渲染和候选证据排序；该状态独立于个股五态。
- `knowledge/research/logic_cases/{case_id}/current.json`：当前 Logic Case；`history/` 保存不可变版本，便于复盘每条逻辑箭头的证据变化。
- `knowledge/research/pipeline/cache/*.json`：当日共享缓存，包含检查日期、源日期、可用状态和失败原因。

运行数据由 `.gitignore` 排除。
